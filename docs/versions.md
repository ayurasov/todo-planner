# Версии и release notes

Документ предназначен для отображения истории версий в интерфейсе приложения. Каждый релиз оформляется отдельным заголовком `## Версия X.Y.Z` и содержит пользовательское описание изменений без технических деталей, не нужных конечному пользователю.

## Версия 1.0.3

В версии обновлена работа с задачами, встречами, подзадачами, комментариями и фильтрами. Основная цель изменений — сделать назначение задач более предсказуемым, а работу с большими списками задач удобнее.

### Комментарии

Комментарии теперь можно редактировать и удалять с учётом прав пользователя:

- автор комментария может изменить свой комментарий;
- удалить собственный комментарий может его автор;
- чужой комментарий может удалить только администратор;
- пользователь не может редактировать чужой комментарий;
- для изменения комментариев учитываются также права на задачу.

В интерфейсе добавлены элементы для редактирования комментария с сохранением форматирования, аналогичного описанию задачи. При изменении комментария система сохраняет информацию о том, что он был отредактирован.

### Новые фильтры в «Задачах команды»

В разделе «Задачи команды» добавлены компактные фильтры:

- **7д** — показать все невыполненные задачи и задачи, выполненные за последнюю неделю;
- **14д** — показать все невыполненные задачи и задачи, выполненные за последние две недели.

Фильтры отображаются в сокращённом виде, чтобы не перегружать панель управления. Подробное описание фильтра доступно при наведении курсора.

### Фильтр исполнителей

Список исполнителей теперь формируется только по тем задачам, которые пользователь действительно может видеть. Благодаря этому в фильтре не появляются сотрудники, у которых нет доступных задач в текущем разделе.

Для встречи в списке исполнителей учитываются:

- участники встречи;
- исполнители задач этой встречи;
- исполнители доступных подзадач, связанных со встречей.

### Улучшено закрытие фильтра

Исправлено поведение раскрывающегося списка исполнителей. Теперь при клике за пределами списка он закрывается автоматически.

При выборе нескольких исполнителей список остаётся доступным для последовательного выбора, а клик по другим элементам интерфейса закрывает раскрытое окно. Обработчик также корректно отключается при уходе со страницы.

### Что это даёт пользователям

- комментарии можно поддерживать в актуальном состоянии и исправлять ошибки без создания новых сообщений;
- в задачах команды проще быстро найти текущую работу и недавно завершённые задачи, отфильтровав по конкретному человеку;
- фильтры исполнителей не содержат лишних пользователей;
- раскрытые списки фильтров больше не остаются открытыми после клика в другой области экрана.

## Версия 1.0.2

В разделе задач улучшена работа с задачами, связанными со встречами и подвстречами. Теперь исполнитель может видеть назначенную ему задачу даже в том случае, если он не является участником самой встречи. При этом доступ к самой встрече и её подвстречам не расширяется: пользователь видит только назначенную ему задачу.

### Задачи из других встреч

Если задача назначена исполнителю из встречи, в которой он не участвует:

- задача отображается в его списке;
- она группируется в отдельном разделе **«Назначенные из других встреч»**;
- в строке задачи показывается понятная информация о подвстрече;
- название основной встречи и внутренние идентификаторы не отображаются;
- переход к недоступной встрече или подвстрече отсутствует;
- дата подвстречи отображается в удобном для пользователя формате, без технической ISO-строки.

Для задач из доступных встреч сохранено прежнее поведение: название встречи и дата подвстречи отображаются как раньше, а переход к встрече остаётся доступным. В `TaskRow` восстановлено корректное отображение названия доступной встречи.

### Фильтры по исполнителям

Фильтры исполнителей теперь формируются с учётом контекста текущего раздела:

- в рамках конкретной встречи отображаются участники встречи и пользователи, назначенные исполнителями задач этой встречи;
- пользователи, которые не относятся к встрече и не назначены на её задачи, в фильтр не попадают;
- список фильтра не содержит лишних сотрудников из общего справочника пользователей.

### Мои задачи

В разделе **«Мои задачи»** фильтр по исполнителям убран, поскольку все отображаемые задачи уже относятся к текущему пользователю.

### Задачи команды

В разделе **«Задачи команды»** добавлены:

- фильтр по исполнителям;
- текстовый поиск по видимым задачам;
- отображение в фильтре только тех исполнителей, по которым есть доступные пользователю задачи;
- поиск по названию задачи и информации о подвстрече;
- корректная работа фильтров без раскрытия данных недоступных встреч.

### Безопасность и доступ

Логика доступа разделена на два уровня:

- назначенный исполнитель получает доступ к своей задаче;
- доступ к встрече по-прежнему определяется участием пользователя и существующими правами.

Пользователь может выполнить назначенную ему работу, но не получает возможности просматривать содержимое встречи, участником которой он не является.

## Версия 1.0

Первая версия системы «По Делу» — веб-планировщик для управления задачами, списками, встречами, исполнителями, сроками и личной/командной работой.

В базовую версию вошли:

- Vue 3-интерфейс с Pinia и Vue Router;
- списки задач и представления «Мои задачи» и «Задачи команды»;
- назначение исполнителей, статусы, приоритеты, сроки и сортировка;
- повторяющиеся задачи и встречи;
- роли и проверки прав на уровне интерфейса;
- mock/localStorage режим для автономной работы;
- архитектура repository/adapter, подготовленная для HTTP backend.

Исторически версия 1.0 была frontend-only MVP. Текущая ветка содержит также production backend, server-side permissions, cookie-сессии, PostgreSQL и Docker-инфраструктуру; эти эксплуатационные возможности описаны в корневом README.

## Формат для будущей визуализации

Для отображения release notes в UI рекомендуется использовать следующие поля:

- `version` — версия, например `1.0.3`;
- `title` — короткое название релиза;
- `summary` — краткое описание;
- `sections` — массив тематических разделов;
- `items` — список пользовательских изменений;
- `releasedAt` — дата выпуска;
- `breaking` — признак несовместимых изменений.

Текущий Markdown сохраняет человекочитаемый формат и одновременно имеет стабильную структуру, которую можно преобразовать в JSON или другой DTO без изменения текста релиза.
